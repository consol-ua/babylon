# Real-Time Translation and Voiceover App Design

## 1. Overview
A macOS desktop application that captures system or microphone audio, translates speech in real-time, synthesizes the translated text using voice cloning (XTTS), and mixes it back with the original audio using a ducking effect. 

## 2. Architecture & Directory Structure
The system uses Tauri as the application wrapper, React/Vite for the UI, and a Python FastAPI sidecar for audio and AI processing.

```text
myProject/
├── src-tauri/                 # Rust core and Tauri configuration
│   ├── tauri.conf.json        # Declares the Python sidecar binary
│   └── src/main.rs            # Rust entry point (minimal, spawns sidecar)
├── src/                       # React + Vite Frontend (TypeScript)
│   ├── App.tsx                # Main UI (Mic selector, start/stop, volume slider)
│   ├── api.ts                 # HTTP and WebSocket client to FastAPI
│   └── index.css              # Tailwind CSS imports
├── backend/                   # Python Backend
│   ├── main.py                # FastAPI server (Endpoints & WebSocket)
│   ├── audio_engine.py        # PyAudio streams, buffer handling, ducking math
│   ├── ai_pipeline.py         # Google STT -> Google Translate -> Coqui XTTS
│   ├── requirements.txt
│   └── build_sidecar.sh       # Script to bundle Python into a standalone binary using PyInstaller
└── package.json               # Node dependencies for Tauri/Vite
```

## 3. Core Audio Pipeline
Implemented in `backend/audio_engine.py`.
- **Framework:** `PyAudio` running non-blocking streams.
- **Ducking Mechanism:**
  - Uses `numpy` for buffer math.
  - While XTTS audio is playing, the original audio buffer is multiplied by a user-defined ducking factor (e.g., 0.2 for 20% volume).
  - The ducked original audio and the XTTS audio arrays are summed and written to the output stream.

## 4. AI Pipeline
Implemented in `backend/ai_pipeline.py`.
- **Speech-to-Text (STT):** Google Cloud STT Streaming API via gRPC.
- **Translation:** Google Cloud Translation REST API processes final STT transcripts.
- **Synthesis:** Coqui XTTSv2, configured to use the `mps` (Metal Performance Shaders) backend for Apple Silicon acceleration.
- Audio generated by XTTS is queued into the `audio_engine` for playback and mixing.

## 5. Frontend & IPC Bridge
- **IPC Protocol:** FastAPI serves HTTP commands (`POST /start`, `POST /stop`, `GET /devices`, `POST /settings`) and a WebSocket connection (`WS /ws`) for real-time state telemetry.
- **Frontend Framework:** React 18, Vite, Tailwind CSS, TypeScript.
- **UI Components:**
  - Device selectors for input/output.
  - Ducking volume slider.
  - Start/stop translation toggle.
  - Live transcript display showing recognized and translated text.
